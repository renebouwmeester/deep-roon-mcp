A safety release: nothing new to learn, several things that now can't go wrong.

- **HTTP mode (`DEEP_ROON_HTTP`) is safe from the browser.** A request with an `Origin` header is refused, and on a loopback address only a loopback `Host` is accepted — before, any web page you opened could have called the write tools through `127.0.0.1`. Bodies over 4 MB are refused.
- **HTTP mode no longer stops when a client hangs up mid-request.** A dropped connection made the whole server exit (an unhandled rejection), taking Roon away from every client until a restart.
- **Zone names are matched safely.** An empty name, or a part of a name that fits more than one zone ("Living Room" with "Living Room Sonos" and "Living Room Bluesound"), is now an error that lists the candidates — before, it picked the first zone it found, also for clearing a queue or setting a volume. The same rule for `roon_ungroup`'s `only`.
- **`roon_volume` refuses a level outside a zone's scale** instead of turning it into the maximum: 30 on a dB scale (−64…0) used to become 0 dB, full volume.
- **`DEEP_ROON_READ_ONLY` fails closed.** Any value other than empty, `off`, `0`, `false` or `no` now means read-only library (`all` still means: only looks). Before, a value like `on` left every write tool on.
- **The internal protocol reader checks every length.** A malformed frame — after a Roon update, or from a hostile device on the network — closes the connection and reconnects, instead of hanging the server or eating memory.
- **A Core at a new address is found again** (a reboot with a new DHCP lease) without restarting Deep Roon, and a half-opened internal connection is closed instead of kept alive.
- **`roon_play_mix`, `roon_favorite` and `roon_listen_later_set` take `profile`,** like the reads they go with — on a Core with several profiles they acted on the default profile before.
